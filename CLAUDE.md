# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

MOAB: Warfront is an online, turn-based island-conquest strategy game for 2–6 players, in the spirit of *Mother Of All Battles* (1994). Players start with one coastal city on a map of the Earth, build units, capture cities and ferry armies across the sea. One React codebase will ship to the web, iOS and Android (Capacitor) and Discord (an Activity plus a bot).

- Design doc (rules, settings, architecture, protocol, roadmap): https://claude.ai/artifact/RfYm2EWRtz6m1UU3pGc5c7
- Screen mockups: https://claude.ai/artifact/GkGQvWpWT2AHkHFHweoGHk

The name, art and icons are original. Never copy names, art or text from the original game.

## Where we are

- **Phase 1 (done):** rules engine, world map and a hot-seat web version for play-testing on one device.
- **Phase 2 (built, gate test passing):** online play on the web. A single Node process (Express + Socket.IO) and PostgreSQL. The server owns every match and sends each seat only `viewFor(state, seat)`. Guest accounts, lobbies by code, live sequential turns with a turn clock, bots in empty seats, chat, recovery after a restart. Still to do: the four-people play-test from the gate.
- Later: async play and notifications, then Discord, then iOS/Android, then public launch. Follow the roadmap in the design doc. Don't build later phases early.

## Commands

```bash
npm install
npm run dev          # hot-seat web version, http://localhost:5173
npm run db:up        # local Postgres in Docker on port 5434 (dev db warfront, test db warfront_test)
npm run server       # game server on http://localhost:3100; applies migrations at start
npm run db:migrate   # apply migrations without starting the server
npm test             # Vitest, all packages; server DB tests skip if Postgres is down
npm run test:db      # the same, but DB tests fail instead of skipping (any shell)
npm run typecheck    # tsc for packages/shared, apps/web and apps/server
npm run build        # production build of apps/web
npm run maps         # regenerate every map in packages/shared/src/world/maps (slow: ~10 min)
npm run maps -- europe-small-v1   # one map
npx vitest run packages/shared/test/rules.test.ts   # one file
```

Before calling work done, run `npm run typecheck` and `npm test`. For server changes, have Postgres up and run `npm run test:db`. For UI changes, also run `npm run build`.

Copy `apps/server/.env.example` to `apps/server/.env` before running the server (it needs `DATABASE_URL` and an `AUTH_SECRET` of 32+ characters). The web client finds the server at `VITE_SERVER_URL` (default http://localhost:3100).

## Engine rules that must stay true

- **The server is the only judge.** Every action goes through `applyAction(state, seat, action)`. Clients send intentions, never outcomes.
- **Pure and immutable.** `applyAction` clones its input and never changes it. `applyActionInPlace` is only for bots and other trusted batch code.
- **Refuse before changing anything.** Every `fail(...)` / `RuleError` must happen before the first mutation, because `applyActionInPlace` depends on it. Keep validation at the top of each handler.
- **Deterministic.** Never use `Math.random`, `Date.now` or iteration over unordered data in engine code. All randomness goes through `nextRandom(s.rng)`, so a match replays exactly from its seed and action log. The seed must never reach a client.
- **Hidden information stays hidden.** Anything sent to a player goes through `viewFor`. It must leave out:
  - enemy units out of sight
  - submarines not next to that player's destroyer
  - other players' cargo and production
  - start picks before turn 1
  - the RNG

  If you add a field to `GameState`, decide its visibility in `view.ts` and add a test in `view.test.ts`.
- **Events say who saw them.** Use `emit(s, event, involves, at)`. `finish()` fills in `seenBy` from `involves` plus whoever can see `at`.
- **Rule numbers live in `units.ts`** (stats, `ROUND_WIN`, `CAPTURE_CHANCE`, `START_SPACING`, …). Don't scatter magic numbers.
- **Seats are 0-based** in code and shown as 1–6 in the UI.

## Map

- Eight regions (World, Africa, Asia, Europe, North America, South America, ASEAN and Australia, and Velgard, an original fantasy continent), each in three sizes: Small (~2,500 land tiles, suggested for 2–3 players), Standard (~5,000, 4–5 players) and Detailed (~15,000). The suggestions are advice; any size takes 2–6 players.
- A match stores its map in `mapVersion` and settings carry `map` and `mapSize`. Engine code gets the map with `mapOf(s)`; never assume World. World Standard is `world-v1`, the original 180 × 90 map, kept byte-identical so saved matches replay.
- Only World wraps east to west. Regional maps have hard edges: `inBounds` before `tileIndex`, and moves off the edge fail with `off-map`. Always use the map's `wrapX`, `distance` and `neighbours`; never do raw `x ± 1` arithmetic.
- Maps other than World Standard load on demand: `await loadMap(version)` before `createMatch`, replaying or viewing a match on it. The server should `loadAllMaps()` at start.
- Cities: capitals of the larger countries first, then major population and cultural centres; city lists carry a tier (1 = every size, 2 = Standard and up, 3 = Detailed only). No two cities sit on neighbouring tiles (Small maps space them wider); where they would, the capital stays. A port must open on real sea, not a lake.
- Velgard's names and coastline are original. Never borrow places or names from published fantasy settings.
- To change terrain, cities or straits, edit `scripts/maps.config.mjs`, `scripts/cities/*.json` or `scripts/velgard.mjs` and run `npm run maps -- <version>`. Coastline data is Natural Earth (public domain).
- Tile index is `y * cols + x`. Use the map's `tileIndex` / `tilePoint` rather than writing it out.

## Rules decided so far

From the design doc: sequential turns; live or async; Auto or hidden Pick starts (everyone picks at once, and on a clash within 12 tiles the later seat keeps the spot); bomber blast radius 2; spectators in public matches see the map two rounds behind.

Settled while building phase 1, and open to change if the user asks:
- A tile holds one owner's units, with no stacking limit.
- The attacker never moves into the tile it won.
- Fighters (16) and bombers (30) carry fuel (`UnitStats.fuel`, `Unit.fuel`) across turns: 1 per tile, refilled on entering your city (fighters also your carrier) and at turn start in a base; at 0 away from a base they crash. Aircraft without a tank (flying paratroopers) must end the turn at a base: they fly to the nearest one in reach or are lost. Aircraft cannot enter a city that is not theirs, except a paratrooper about to land. Bombers have attack 0 and keep the one-use blast, so a fighter always downs one. (User's call, 2026-11-01.)
- Players start with one city building tanks and no units.
- Paratroopers are aircraft until they land: they fly 8 tiles like a fighter, over land or sea, cannot attack, and follow the aircraft turn-end rule. The `land` action brings one down where it is (land, not mountains) and makes it a tank for good; landing on a city you don't own is a capture attempt. Only tanks capture by moving in. (User's call, 2026-11-01; replaced the old 8-tile `drop`.)
- Fighters and bombers away from a base with less than `LOW_FUEL` (5) fuel show a warning. A flying paratrooper's fuel is its moves left this turn.
- A tank or paratrooper always takes a neutral city. An enemy city with no land defenders falls half the time (`CAPTURE_CHANCE`), and the unit is lost otherwise. (User's call, 2026-11-01.)

If a rule is unclear, check the design doc first, then ask. Don't invent rules silently.

## Tests

- Vitest. Tests live in `packages/shared/test/*.test.ts`.
- Build scenarios with `blankGame()`, `own()`, `put()` and `sync()` from `test/helpers.ts`. `blankGame` parks a submarine per seat in the South Pacific so nobody is eliminated by accident. Pass `keepAlive: false` when testing elimination or victory.
- Check terrain preconditions with `expectTerrain(x, y, 'land')` so tests fail clearly if the map changes.
- Test probabilities with the `trials()` pattern (re-seed a cloned state many times) and assert a range, not an exact value.
- `match.test.ts` runs full bot matches with `checkInvariants` after every turn. Keep it passing when changing rules.

## Web client

- Dark tactical UI. Tokens are in `apps/web/src/theme.ts` and `styles.css`. Fonts are Chakra Petch (display) and Barlow (body). Amber `#F2A93B` is the single accent.
- Every player has a colour and an emblem (circle, triangle, square, diamond, hexagon, star). Never rely on colour alone.
- Unit icons are original SVG paths in `apps/web/src/icons.ts`, shared by the canvas and React. Keep them in sync with the mockups.
- The map is drawn on a canvas (`src/map/draw.ts`). Terrain, fog and explored masks are one-pixel-per-tile images scaled up.
- Accessibility: real `<button>`s, `aria-label` on icon-only buttons, touch targets of at least 44 px, and text contrast of at least 4.5:1.
- Mobile first: check layouts at 390 px wide as well as desktop.
- Browser storage is a convenience only. Wrap every `localStorage` call in try/catch.
- Map effects (`src/map/effects.ts`) are built only from `view.log`, so they show nothing a player did not see. Hot-seat turns open with a replay of events since that player's last turn. Honour `prefers-reduced-motion` with still highlights.
- Hot-seat saves: named saves in the browser and downloadable save files (`src/game/saves.ts`). The file format and its checks are in `packages/shared/src/protocol/save.ts`: run `readSaveFile`, load the map, then `checkSavedGame`. A save holds the full state, seed included, so never offer one for an online match.

## Phase 2 notes (agreed design)

- PostgreSQL (not MongoDB). Plain tables for users, user_logins, push_tokens, matches, seats; JSONB for settings and turn snapshots; `match_actions` keyed `(match_id, rev)`. Seat numbers in the database are 0–5, like the engine.
- Accept an action with one guarded transaction: `UPDATE matches SET rev = rev + 1 WHERE id = $1 AND rev = $2`, then insert the action.
- Live state stays in server memory. Snapshot at each turn start; recover by replaying actions from the last snapshot.
- Turn deadlines and notifications are a Postgres `jobs` table claimed with `FOR UPDATE SKIP LOCKED` (or pg-boss). No Redis. Use Socket.IO's Postgres adapter if a second instance is ever needed.
- Validate every message with zod schemas kept in the shared package (`src/protocol`). Client input uses strict objects (unknown keys are refused); server output uses plain objects so older clients ignore new fields. Never trust a seat sent by a client; take it from the signed-in user.
- Every payload names its `matchId`, because one socket can follow several matches.
- When an engine type changes, update its schema: `protocol.test.ts` checks the action and settings schemas match the engine types exactly, and parses real bot-match views.
- A player action carries `expectedRev` (the view's rev) and a `clientActionId`; a repeated id gets the first reply. `pickStart` and `resign` skip the rev check, since picks are made all at once and resigning does not depend on the map.
- Keep the stack lean: React, Vite, Capacitor, Express, Socket.IO, `pg`, zod, the Discord Embedded App SDK, web-push. No ORM. Ask before adding other dependencies.

## Conventions

- TypeScript strict, ES modules, `moduleResolution: Bundler`.
- No runtime dependencies in `packages/shared`, except zod inside `src/protocol`. A test fails if any other file imports it.
- Comments explain why, not what. User-facing text is plain and short.
- Commit messages: a short summary line, a blank line, then bullet points for notable changes.
